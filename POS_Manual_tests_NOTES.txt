        instead of an honest "cannot show this".

          Settings -> Customer Display -> Display character set

            Western European (accents kept)
            Arabic (Windows-1256)
            Arabic, reversed

         reads TOTAL A PAYER. Switch to English -> TOTAL DUE.

         product -> still ???????. That is correct.

F.  TESTING THE POLE DISPLAY WITHOUT A POLE DISPLAY
=======================================================

You do not need the hardware. com0com is ALREADY INSTALLED
on this PC (C:\Program Files (x86)\com0com). It joins two
COM ports back to back, so the POS writes into one end and
you read the other:

    [ POS APP ] --> COM8  ~~com0com~~  COM9 <-- [ listener ]

STEP 1 - prove the listener itself works (no ports needed):

    cd D:\POS-APP\Front-End
    .	ool\pole_display_listener.ps1 -SelfTest

  It decodes a synthetic frame and must print
  "Self-test passed". If this fails, the fault is in the
  script, not in the POS - do not go looking at wiring.

STEP 2 - make the virtual pair. NEEDS AN ADMIN PROMPT
  (right-click PowerShell -> Run as administrator):

    cd "C:\Program Files (x86)\com0com"
    .\setupc.exe install PortName=COM8 PortName=COM9
    .\setupc.exe list

  Then check Windows agrees:

    [System.IO.Ports.SerialPort]::GetPortNames()

  It must now list COM8 and COM9 beside your real port.

STEP 3 - start the fake display on the FAR end:

    cd D:\POS-APP\Front-End
    .	ool\pole_display_listener.ps1 -Port COM9

  A two-line display is drawn in the terminal. Leave it up.

STEP 4 - point the POS at the NEAR end:

    Settings -> Customer Display
      - switch it ON
      - COM port: COM8      <- it must be IN THE LIST. If
        COM8 is missing, refresh; if still missing, step 2
        did not take.
      - characters per line: 20 (match the -Width you ran
        the listener with)
      - baud 9600, 8 data bits, no parity, 1 stop bit

STEP 5 - watch it:

    - Press TEST in Settings -> the welcome message appears
      in the terminal box, padded to 20 characters.
    - Ring a sale and open the payment dialog -> line 1
      reads TOTAL DUE and line 2 the amount, and it updates
      as the total changes.
    - Close the payment dialog -> it goes back to the
      welcome message.
    - The "writes:" counter goes up on every write. If the
      counter never moves, the POS is writing to a different
      port than the one you paired - which is the whole bug
      class this work removes.

WHEN YOU ARE DONE (admin prompt):

    cd "C:\Program Files (x86)\com0com"
    .\setupc.exe remove 0

TROUBLESHOOTING:
  - "Could not open COM9" -> something else holds it open.
    Close other terminals, or the POS itself if you pointed
    it at COM9 by mistake (it must be COM8).
  - Text appears but padding looks wrong -> -Width does not
    match "characters per line" in Settings.
  - Nothing at all, and Test says the port is not on this
    machine -> that is the new error doing its job. Read the
    port list it prints.

SECOND, EVEN SIMPLER PATH - the WEB customer display:
  Settings -> Customer Display -> the web display serves a
  full customer-facing screen over HTTP on port 8181. Open
  the URL it shows on your phone or a second browser tab and
  you get the cart and total live, with no serial anything.
  It does NOT exercise the COM path, so use it to check the
  CONTENT and com0com to check the WIRING.
