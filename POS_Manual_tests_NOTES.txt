[39] NEW - POS SESSIONS: two things, and one answer.

     (a) THE ANSWER first, because it explains your last line.
         There IS no "POS session" table, by design. A session is a
         row in the SHIFT table with a PosDeviceId set and a status
         of 10-13, while an attendance shift uses 0-1. They share
         one table on purpose - the ranges are kept apart so the
         two can never be mistaken for each other. So nothing is
         missing from the database; you were looking for a table
         that was never meant to exist.

     (b) DATABASE RESET does not clear sessions. Confirmed: the
         reset only knows Products / Customers / Documents /
         Everything, and touches no shift or session rows at all.
         So wiping Documents leaves every past session behind, and
         the register still thinks it has history. Sessions belong
         with Documents (same money, same day) - I will add them
         there.

     (c) THE TIMER on top of User Info. It counts attendance hours
         and should only appear when a USER clocks in, never when a
         register opens. Already ruled out the obvious cause: the
         sidebar clock watches "shift status = 0" and opening a
         session writes status = 10, so those two do not overlap
         and the session is not what is switching it on. Something
         else is - needs a proper look, not a guess.

[8] DONE - CASH DRAWER NOW ACTUALLY OPENS.

    You never had to answer the wiring question - all three are
    built and you PICK one on screen.

    Settings -> Printers -> (tap a printer) -> Cash Drawer:
      - turn "Open cash drawer" ON
      - "How the drawer is connected":
          * Through the receipt printer (RJ11)  <- start here, this
            is how ~90% of drawers are wired. Nothing else to fill in.
          * Network - printer or drawer IP      <- the ONLY one that
            works on the Android tablets. Needs the IP + port 9100.
          * Serial port (COM)                   <- COM3 + 9600, etc.
      - press "Test Drawer Open".

    (a) The drawer opens. If it does not, the message now tells you
        WHY (wrong printer, refused RAW job, host unreachable...).
        Before today that button lied: it waited 0.7 s and said
        "Test signal sent" without sending anything at all.
    (b) Ring up a CASH sale -> the drawer pops the moment the sale
        is banked, before the receipt prints.
    (c) Ring up a CARD sale -> stays shut, PROVIDED you have ticked
        "Open cash drawer" on at least one payment type (Settings ->
        Payment Types). If you have ticked it on NONE, every sale
        opens the drawer - deliberate, so the switch above works on
        its own without you hunting through payment types.
    (d) On the TABLET: pick Network and enter the printer's IP. The
        other two options say they need Windows instead of failing
        silently.
    (e) Two tills, different wiring: the transport/IP/COM port are
        stored PER TERMINAL, so the Windows till and the tablet do
        not overwrite each other. The command bytes are shared.
