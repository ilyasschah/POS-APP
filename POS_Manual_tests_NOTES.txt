[B5] ANDROID SILENT PRINTING - BUILT, NEEDS A REAL PRINTER.
     Item 9, the biggest thing left. The tablets showed the
     system print dialog on every print because that is the
     ONLY thing Android could do: Printing.listPrinters()
     has no Android implementation and directPrintPdf
     reports directPrint:false. A modal asking which printer
     to use, in the middle of closing a sale.

     Now every printer has a CONNECTION setting:
       Printer Settings -> <station> -> Connection
         This computer (Windows printer)   <- default
         Network printer (Wi-Fi / LAN)     <- new
     Pick Network and enter the printer's IP and port
     (9100). Receipts, kitchen tickets and Z-reports all go
     that way - they share one dispatcher.

     HOW IT PRINTS, and why it matters to you: the receipt
     is NOT rebuilt as printer text commands. The PDF you
     already get is rendered to pixels and sent as a bitmap.
     That means the logo, the barcode, the margins and -
     the one that decides it - the ARABIC comes out exactly
     as the PDF shows it. A text-command printer uses its
     own built-in font, which on almost every unit has no
     Arabic at all.

     (a) Printer Settings -> Receipt -> Connection ->
         Network printer. Enter the IP, leave port 9100.
     (b) Press TEST PRINT. A demo receipt must come out with
         NO dialog. 🚨 On the tablet this button used to be
         disabled whenever no Windows printer was found -
         which on Android is always - so it could never be
         pressed on the device that needed it.
     (c) Ring a real sale -> the receipt prints silently.
     (d) Turn the printer OFF and ring another sale. You must
         get a message naming the address, e.g. "Could not
         reach the printer at 192.168.1.50:9100". 🚨 This is
         the important one: checkout used to swallow every
         print error, so a dead printer looked exactly like
         a printer that printed. That is the same bug you
         found on the till in August.
     (e) Type the address wrong on purpose - "192.168.1.50:9100"
         in the address field, or "http://..." - it tells you
         what is wrong instead of failing at DNS.
     (f) Paper size 58mm vs 80mm: the test print is a ruler
         the full width of the head. If the setting is wrong
         the rule wraps and the comb shears - visible at a
         glance, no measuring.
     (g) On the WINDOWS till, leave Connection on "This
         computer". Nothing about it should change. (Every
         printer ships defaulted to it - a default of
         Network with no address would break every existing
         till on upgrade.)
     (h) Set the till to Windows and the tablet to Network
         for the SAME printer. Both must keep their own
         answer - the connection, address and port are
         per-terminal, like the cash-drawer wiring.

     ⚠️ WHAT I COULD NOT TEST: a real thermal printer. There
     is none here. What IS proven: the ESC/POS bytes are
     encoded and decoded back to the exact image (27 tests),
     and a 200KB job arrives whole and in order over a real
     socket (10 tests). What no test can tell me is whether
     YOUR printer likes the raster - if it prints garbage,
     say so and the first thing to try is a smaller band
     size.

     NOT DONE YET: Bluetooth and USB-OTG. LAN first was the
     plan; if your tablets' printers are not on the network,
     tell me and that becomes the next piece.
